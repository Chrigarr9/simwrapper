## Implementation Details

### Task 1: Integration Fixes

**1. ColorBy Type Override**

All three Plotly cards (ScatterCard, HistogramCard, PieChartCard) now support explicit YAML type configuration:

```typescript
// Priority 1: Use YAML-configured type if available
const yamlConfig = props.colorByOptions?.find(opt => opt.attribute === attribute)
if (yamlConfig?.type === 'numeric' || yamlConfig?.type === 'categorical') {
  return yamlConfig.type
}

// Priority 2: Auto-detect from data
// ... existing auto-detection logic
```

**Use Case:** Numeric mode IDs (1=car, 2=bike, 3=walk) have <15 unique values and would normally be treated as categorical by auto-detection. The YAML can now override:

```yaml
colorBy:
  attributes:
    - attribute: mode_id
      label: Transport Mode
      type: categorical  # Explicit override prevents numeric colorscale
```

**2. Plotly Legend/Colorbar Title Enhancement**

**ScatterCard:** Numeric colorbar now uses title object form:
```typescript
colorbar: {
  title: {
    text: attributeLabel,
    font: { color: textColor, size: 11, family: fontFamily },
    side: 'right'
  }
}
```

**HistogramCard:** Both numeric colorbar and categorical legend titles:
```typescript
// Numeric mode
colorbar: {
  title: {
    text: attributeLabel,
    font: { color: textColor, size: 11, family: fontFamily },
    side: 'right'
  }
}

// Categorical mode
legend: {
  title: {
    text: legendTitle,
    font: { color: textColor, size: 11, family: fontFamily }
  }
}
```

**PieChartCard:** Legend title shows attribute label:
```typescript
legend: {
  title: {
    text: attributeLabel,
    font: { color: textColor, size: 11, family: fontFamily }
  }
}
```

**ScatterCard legend title:** Dynamically uses colorBy attribute label or colorColumn:
```typescript
const legendTitle = colorByActive && colorByType === 'categorical'
  ? (props.colorByOptions?.find(opt => opt.attribute === props.colorByAttribute)?.label || props.colorByAttribute)
  : hasCategories ? props.colorColumn : undefined
```

**3. PieChartCard colorByOptions Prop**

Added missing `colorByOptions` prop to PieChartCard interface:
```typescript
colorByOptions?: Array<{ attribute: string; label: string; type: string }>
```

This enables:
- YAML type override in PieChartCard
- Attribute label resolution for legend titles
- Consistent prop interface across all card types

**4. ColorBySelector Event Name Fix**

Changed emit from camelCase to kebab-case for Vue 2.7 compatibility:
```typescript
// Before (not working)
emit('update:modelValue', target.value)

// After (working)
emit('update:model-value', target.value)
```

**Root Cause:** Vue 2.7 doesn't auto-convert event names between camelCase and kebab-case like Vue 3. Template uses `@update:model-value`, so emit must match exactly.

## Decisions Made

**1. YAML Type Override Priority**
- YAML-configured type takes precedence over auto-detection
- Enables explicit control for edge cases (numeric IDs displayed categorically)
- Auto-detection remains as fallback for unconfigured attributes

**2. Plotly Title Object Form**
- Use title: { text, font, side } instead of title: string
- Provides consistent font styling across legends and colorbars
- Enables side: 'right' positioning for colorbars

**3. ColorBySelector Event Naming**
- Use kebab-case for Vue 2.7 event names
- Matches template @update:model-value exactly
- Avoids camelCase conversion assumptions from Vue 3

**4. Attribute Label Resolution**
- All cards read colorByOptions for label lookups
- Fallback to toTitleCase(attribute) if not configured
- Ensures human-readable legend/colorbar titles
