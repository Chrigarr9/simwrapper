# Phase 04.3: Scatter Plot Color-By Selector and Cross-Card Sync - Context

**Gathered:** 2026-02-16
**Status:** Ready for planning

<domain>
## Phase Boundary

Add a dashboard-level color-by attribute selector that controls how data points are colored across ALL card types (scatter, map, histogram, pie). The selector is a single central control — not per-card dropdowns. Changing the color-by attribute updates every card in the dashboard simultaneously.

</domain>

<decisions>
## Implementation Decisions

### Selector placement & style
- ONE central color-by selector in the table header area (dashboard-level control, not per-card)
- Dropdown menu (click to open list of attributes)
- Includes a "None" option to disable color-by and return to default single-color rendering
- Reuse the same dropdown component that MapCard currently uses for its color-by selector — visual consistency across the dashboard
- Default state on load: first configured attribute is active (not "None")

### Coloring behavior
- Supports BOTH categorical coloring (discrete categories like transport mode) AND numeric coloring (gradient scales like distance)
- Show a color legend when color-by is active
- Legend entries are clickable/filterable — clicking a legend category filters data (consistent with MapCard's legend filtering)
- Comparison mode interaction: baseline stays gray, filtered data gets color-by colors (existing comparison pattern preserved)

### Cross-card sync
- ALL cards react to the central color-by selector — scatter, map, histogram, pie
- No per-card override — one color-by state controls everything
- This is a dashboard-level concern, not a card-level concern
- The central selector replaces MapCard's existing per-card color-by dropdown (MapCard reads from the shared state instead)

### YAML configuration
- Top-level `colorBy` section in dashboard YAML (not under `table` or per-card)
- Attributes explicitly listed in YAML — no auto-detection from data columns
- Type (categorical vs numeric) auto-detected from actual data values — not specified in YAML
- Default active attribute is the first one in the configured list

### Claude's Discretion
- Internal architecture for the shared color-by state (LinkageManager extension vs new manager vs simple Vuex state)
- How to migrate MapCard's existing color-by dropdown to use the new central state
- Color scale choices for numeric attributes
- Exact positioning within the table header area

</decisions>

<specifics>
## Specific Ideas

- The user emphasized reusing the exact same dropdown component that MapCard already uses — not building a new one, but extracting/sharing the existing one
- The pivot from per-card to central selector was driven by realizing "if all cards sync anyway, why have redundant dropdowns?"
- Histogram should group/color bars by the selected attribute; pie should show categories from the selected attribute
- This effectively promotes color-by from a MapCard feature to a dashboard-level feature

</specifics>
