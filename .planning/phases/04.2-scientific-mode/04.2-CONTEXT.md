# Phase 4.2: Scientific Mode - Context

**Gathered:** 2026-01-30
**Status:** Ready for planning

<domain>
## Phase Boundary

Create a "scientific" styling profile for paper-ready visualizations with interactive export functionality. Users can toggle scientific mode like light/dark mode, and export individual cards or all cards in their current state.

**In scope:** Scientific styling, per-card export button, "Export All" functionality, PNG/SVG formats
**Out of scope:** YAML-driven headless/batch export (Phase 4.3), automated export pipelines

</domain>

<decisions>
## Implementation Decisions

### Scientific Styling

- **Background:** Pure white (#FFFFFF) for maximum print contrast
- **Font family:** Arial/Helvetica - most common in scientific figures
- **UI chrome:** Hide ALL interactive elements (zoom buttons, tooltips, hover effects) - pure visualization only
- **Color palette:** Colorblind-safe palette (Viridis, ColorBrewer style)
- **Marker differentiation:** Different shapes for scatter plots (circle, square, triangle, diamond) to distinguish series when printed B&W
- **Line differentiation:** Different line styles for line charts (solid, dashed, dotted, dash-dot) for B&W printing
- **Architecture:** Extend existing StyleManager with a `scientific` section - keep theming centralized

### Export Formats & Resolution

- **Formats supported:** PNG + SVG (no PDF for now)
- **Default PNG resolution:** 300 DPI - standard for print publications
- **Dimension configuration:** Global default in settings + per-card override via YAML (`exportWidth`, `exportHeight`)
- **Map export method:** Canvas snapshot via deck.gl `toDataURL()` - includes base map, fast and simple

### Export UI & Workflow

- **Per-card export button:** In card header, next to fullscreen button
- **Button visibility:** Always visible (in all modes, not just scientific)
- **Export All button:** Dashboard toolbar (top), alongside other dashboard controls
- **Filename convention:** Card title based by default (e.g., `histogram-income.png`), with YAML override via `exportName` property

### Mode Activation

- **Activation method:** Toggle in UI, same location as light/dark mode switcher → becomes three-way: Light / Dark / Scientific
- **Persistence:** Yes, saved to localStorage - remembered across sessions
- **YAML override:** No - always user preference, YAML cannot force scientific mode

### Claude's Discretion

- Exact colorblind-safe palette selection (specific colors)
- Specific marker shape assignments per series
- Export button icon design
- Progress feedback during "Export All" operation
- SVG export implementation details (Plotly vs custom)

</decisions>

<specifics>
## Specific Ideas

- "If this is printed black and white, there should still be a differentiation between the different markers and line styles"
- Integrate scientific styling into existing StyleManager (not a separate system)
- Export button always visible, not hidden behind scientific mode - users might want to export in normal mode too
- Three-way mode toggle (Light/Dark/Scientific) in same location as current theme switcher

</specifics>

<deferred>
## Deferred Ideas

- **Phase 4.3: YAML-driven export scripts** — Define export state in YAML (filters, colorBy, specific data), run headless without hosting SimWrapper, generate output folder with all graphics. Batch/automation workflow.
- Vector export for maps (GeoJSON→SVG) — complex, may lose base map; canvas snapshot sufficient for now

</deferred>
