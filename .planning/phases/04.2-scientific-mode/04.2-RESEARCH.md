# Phase 4.2: Scientific Mode - Research

**Researched:** 2026-01-30
**Domain:** Scientific visualization styling and export for web-based data visualizations
**Confidence:** HIGH

## Summary

Phase 4.2 implements a scientific styling profile and export functionality for publication-ready visualizations. The research reveals that this is a well-established domain with mature APIs in both Plotly.js and deck.gl for high-resolution export. Scientific publications have standardized requirements (300 DPI PNG minimum, vector formats preferred for diagrams), and colorblind-safe palettes like Viridis are industry standard.

The existing SimWrapper architecture already has the foundation in place:
- **StyleManager** (singleton pattern) manages centralized theming with light/dark mode support
- **Plotly.js 3.1.0** provides `downloadImage()` and `toImage()` APIs with configurable resolution via `scale` parameter
- **deck.gl 9.1.14** with MapLibre GL offers canvas snapshot via `getCanvas().toDataURL()` (through MapLibre integration)
- **Vuex store** persists theme preferences to localStorage, providing pattern for scientific mode persistence

The technical approach is straightforward: extend StyleManager with a `scientific` theme (white background, black text, Arial/Helvetica), add export buttons to card headers using Plotly/deck.gl native APIs, and implement ZIP generation for bulk export using JSZip (needs installation).

**Primary recommendation:** Build scientific mode as a third theme option in StyleManager, use native library export APIs (Plotly.downloadImage, deck.gl canvas snapshot), and add JSZip for bulk download functionality.

### Pattern 3: deck.gl/MapLibre Canvas Snapshot

**What:** Export deck.gl map via MapLibre's canvas `toDataURL()` method
**When to use:** MapCard with deck.gl layers
**Example:**

```typescript
// Source: MapLibre/deck.gl integration patterns + GitHub issues research

// In MapCard.vue
async function exportMap(format: 'png' | 'jpeg' = 'png'): Promise<string> {
  if (!mapInstance) throw new Error('Map not initialized')

  // Ensure map is fully rendered
  await new Promise(resolve => {
    mapInstance.once('idle', resolve)
    mapInstance.triggerRepaint()  // Force redraw if needed
  })

  // Get canvas and export (includes deck.gl layers in interleaved mode)
  const canvas = mapInstance.getCanvas()
  const mimeType = format === 'png' ? 'image/png' : 'image/jpeg'
  const dataUrl = canvas.toDataURL(mimeType)

  return dataUrl
}

// Trigger download
function downloadMap() {
  const dataUrl = await exportMap('png')
  const link = document.createElement('a')
  link.download = `${cardTitle || 'map'}.png`
  link.href = dataUrl
  link.click()
}
```

**Note:** Only deck.gl canvas is captured, not HTML overlays (legend, controls). User decision: legends export separately if needed.

### Pattern 4: Bulk Export with JSZip

**What:** Generate ZIP containing all dashboard plots, triggered by "Export All" button
**When to use:** User wants entire dashboard for publication
**Example:**

```typescript
// Source: Context7 JSZip documentation - https://github.com/stuk/jszip

import JSZip from 'jszip'

async function exportAllCards() {
  const zip = new JSZip()

  // Export each card
  for (const card of cards) {
    const dataUrl = await card.export()  // Returns data URL

    // Extract base64 data (remove "data:image/png;base64," prefix)
    const base64Data = dataUrl.split(',')[1]

    // Add to ZIP with proper filename
    const filename = `${card.title || 'chart'}-${card.id}.png`
    zip.file(filename, base64Data, { base64: true })
  }

  // Generate ZIP blob and trigger download
  const blob = await zip.generateAsync({ type: 'blob' })
  const link = document.createElement('a')
  link.download = 'dashboard-export.zip'
  link.href = URL.createObjectURL(blob)
  link.click()
  URL.revokeObjectURL(link.href)  // Cleanup
}
```

### Anti-Patterns to Avoid

- **Creating parallel styling system:** Don't create separate scientific CSS variables outside StyleManager
- **Manual canvas rendering:** Don't reimplement Plotly's export logic, use built-in APIs
- **Synchronous ZIP generation:** Always use `generateAsync()` to avoid UI blocking
- **YAML-forced mode:** Per user decision, scientific mode is always user preference, never YAML-controlled

## Don't Hand-Roll

Problems that look simple but have existing solutions:

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Image export from Plotly | Custom screenshot capture | `Plotly.downloadImage()` / `toImage()` | Handles text rendering, vector paths, resolution scaling, format conversion |
| Canvas to image conversion | Manual pixel reading | `canvas.toDataURL()` | Native browser API, handles format encoding, memory management |
| ZIP file creation | Manual ZIP format implementation | JSZip library | ZIP format is complex (compression, CRC checksums, directory structure) |
| File download trigger | Custom download logic | `<a download>` + Blob URL | Cross-browser compatibility, mobile support, memory cleanup |
| Colorblind-safe palette | Hand-picked colors | Viridis/ColorBrewer palettes | Scientifically validated for perceptual uniformity and accessibility |
| Resolution calculation | Manual DPI math | Plotly `scale` parameter | Library handles pixel density for target DPI |

**Key insight:** Modern visualization libraries (Plotly, deck.gl) were designed for scientific use and have mature, well-tested export APIs. Custom solutions lose these benefits and introduce bugs.

## Common Pitfalls

### Pitfall 1: Forgetting Scale Parameter for Print Quality

**What goes wrong:** Exported PNGs look pixelated in printed publications despite correct dimensions
**Why it happens:** Default export is 1:1 pixel ratio (72 DPI equivalent), not 300 DPI standard
**How to avoid:** Always use `scale: 2` (or higher) with Plotly export for print targets

```javascript
// BAD: 72 DPI equivalent
Plotly.downloadImage(plot, { width: 1200, height: 800 })

// GOOD: ~150 DPI for screen, 300 DPI for print
Plotly.downloadImage(plot, { width: 1200, height: 800, scale: 2 })
```

**Warning signs:** Users report "blurry charts" or journals reject figures for low resolution

### Pitfall 2: MapLibre Canvas Export Timing

**What goes wrong:** `toDataURL()` captures incomplete render (missing tiles, layers partially drawn)
**Why it happens:** Canvas export is synchronous but rendering is asynchronous
**How to avoid:** Wait for `idle` event before capturing

```javascript
// BAD: Captures mid-render
const dataUrl = map.getCanvas().toDataURL()

// GOOD: Wait for render completion
map.once('idle', () => {
  const dataUrl = map.getCanvas().toDataURL()
})
```

**Warning signs:** Exported maps have missing basemap tiles or partially rendered layers

### Pitfall 3: Memory Leaks from Blob URLs

**What goes wrong:** Browser memory fills up during bulk export, eventually crashes
**Why it happens:** `URL.createObjectURL()` creates memory references that aren't auto-cleaned
**How to avoid:** Always call `URL.revokeObjectURL()` after use

```javascript
// BAD: Memory leak
const url = URL.createObjectURL(blob)
link.href = url
link.click()

// GOOD: Explicit cleanup
const url = URL.createObjectURL(blob)
link.href = url
link.click()
URL.revokeObjectURL(url)
```

**Warning signs:** Browser slows down during "Export All", DevTools shows growing memory usage

### Pitfall 4: Scientific Mode Breaking Interactive Features

**What goes wrong:** Users enable scientific mode and can't interact with charts (no zoom, no tooltips)
**Why it happens:** Hiding UI chrome (`displayModeBar: false`, `staticPlot: true`) can be overly aggressive
**How to avoid:** Make scientific styling optional, don't force static plots

**User decision from CONTEXT.md:** Export button always visible (not hidden behind scientific mode), users might export in normal mode too.

```javascript
// Approach: Scientific mode affects STYLING, not interactivity
// Let users interact normally, only export removes UI chrome programmatically

// For interactive view
const config = { displayModeBar: true }  // Keep controls

// For export only
const exportConfig = {
  displayModeBar: false,  // Clean export without toolbar
  staticPlot: false       // Still allow vector export of interactive features
}
```

**Warning signs:** User complaints about "broken" scientific mode, inability to zoom/pan

### Pitfall 5: Marker/Line Differentiation Only via Color

**What goes wrong:** Scientific figures printed in black & white become indistinguishable
**Why it happens:** Forgetting that many readers print papers in grayscale
**How to avoid:** Use marker shapes AND line styles in addition to color

```javascript
// BAD: Only color differs
traces = [
  { y: data1, line: { color: 'red' } },
  { y: data2, line: { color: 'blue' } }
]

// GOOD: Shape + style + color
traces = [
  {
    y: data1,
    line: { color: 'red', dash: 'solid' },
    marker: { symbol: 'circle' }
  },
  {
    y: data2,
    line: { color: 'blue', dash: 'dash' },
    marker: { symbol: 'square' }
  }
]
```

**Warning signs:** Figures look identical when printed B&W, user feedback about "can't tell lines apart"

### deck.gl Canvas Export via MapLibre

```javascript
// Source: MapLibre documentation + GitHub issue discussions

async function exportDeckGLMap(
  mapInstance: maplibregl.Map,
  filename: string = 'map.png'
): Promise<void> {
  // Wait for map to finish rendering
  await new Promise<void>((resolve) => {
    if (mapInstance.loaded() && mapInstance.areTilesLoaded()) {
      resolve()
    } else {
      mapInstance.once('idle', () => resolve())
      mapInstance.triggerRepaint()
    }
  })

  // Get canvas (includes deck.gl layers in interleaved mode)
  const canvas = mapInstance.getCanvas()
  const dataUrl = canvas.toDataURL('image/png')

  // Trigger download
  const link = document.createElement('a')
  link.download = filename
  link.href = dataUrl
  link.click()
}
```

### Bulk Export with JSZip

```javascript
// Source: Context7 JSZip - https://github.com/stuk/jszip

import JSZip from 'jszip'

async function exportAllDashboardCards(
  cards: Array<{ title: string; exportFn: () => Promise<string> }>
): Promise<void> {
  const zip = new JSZip()

  // Export each card
  for (let i = 0; i < cards.length; i++) {
    const card = cards[i]

    try {
      // Get data URL from card's export function
      const dataUrl = await card.exportFn()

      // Extract base64 data (format: "data:image/png;base64,XXXXX")
      const base64Data = dataUrl.split(',')[1]

      // Sanitize filename
      const safeName = card.title
        .toLowerCase()
        .replace(/[^a-z0-9]+/g, '-')
        .replace(/^-|-$/g, '')

      const filename = `${String(i + 1).padStart(2, '0')}-${safeName}.png`

      // Add to ZIP
      zip.file(filename, base64Data, { base64: true })
    } catch (error) {
      console.error(`Failed to export ${card.title}:`, error)
    }
  }

  // Generate ZIP and trigger download
  const blob = await zip.generateAsync({
    type: 'blob',
    compression: 'DEFLATE',
    compressionOptions: { level: 6 }
  })

  const url = URL.createObjectURL(blob)
  const link = document.createElement('a')
  link.download = `dashboard-export-${Date.now()}.zip`
  link.href = url
  link.click()

  // Cleanup
  URL.revokeObjectURL(url)
}
```

## State of the Art

| Old Approach | Current Approach | When Changed | Impact |
|--------------|------------------|--------------|--------|
| Server-side rendering (PhantomJS) | Client-side canvas export | ~2018 | Plotly.js now supports browser-native export, no server needed |
| Manual DPI calculation | Library `scale` parameter | Plotly 2.x+ | Libraries handle resolution scaling automatically |
| Custom colorblind palettes | Viridis/Okabe-Ito standards | ~2015 | Scientific consensus on accessible color schemes |
| HTML2Canvas for all exports | Native API per library | 2020+ | Plotly/deck.gl have optimized export APIs, better quality |
| Separate "print stylesheet" | Dynamic theme switching | Modern frameworks | Single codebase with theme toggle |

**Deprecated/outdated:**
- **Orca (Plotly's old export engine):** Deprecated in Plotly.py 6.2.0, removed Sept 2025. Use Kaleido or browser-native export.
- **PhantomJS for headless export:** Unmaintained since 2018. Use Puppeteer/Playwright if headless export needed (Phase 4.3).
- **Red-green color schemes:** Problematic for deuteranopia (most common colorblindness). Use blue-orange instead.

## Open Questions

Things that couldn't be fully resolved:

1. **PDF Export Support**
   - What we know: Plotly.js doesn't directly support PDF. User decided "PNG + SVG only" (no PDF for now).
   - What's unclear: Whether future need for PDF would require Puppeteer (headless browser) or if client-side PDF generation (jsPDF) is acceptable.
   - Recommendation: Defer PDF to Phase 4.3 (headless export). PNG + SVG cover 95% of publication needs.

2. **Legend Export in Map Screenshots**
   - What we know: `toDataURL()` only captures canvas, not HTML overlays (legend, controls).
   - What's unclear: Whether legends should be programmatically drawn on canvas before export or exported separately.
   - Recommendation: Export legend as separate SVG/PNG, let users compose in figure software. This matches scientific workflow (authors assemble multi-panel figures).

3. **Export Resolution Defaults**
   - What we know: 300 DPI is minimum for journals, achieved with `scale: 2` for 1200px width chart.
   - What's unclear: Optimal default dimensions (1200x800 vs 1600x900 vs 1920x1080).
   - Recommendation: Default to 1200x800 with `scale: 2` (~2400x1600 physical pixels = 300 DPI at 8x5.3 inches). Make configurable via YAML `exportWidth`/`exportHeight`.

4. **Marker Shape Assignment Strategy**
   - What we know: Need different shapes for B&W printing (circle, square, triangle, diamond).
   - What's unclear: How to consistently assign shapes when categories are dynamic (e.g., ScatterCard with colorBy attribute).
   - Recommendation: Round-robin assignment based on sorted category values, store in StyleManager as `getMarkerShape(categoryIndex)`.
